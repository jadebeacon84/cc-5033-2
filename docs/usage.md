# 划痕修复使用指南

## 图形入口（主要方式）

划痕修复的主入口是本地审阅工作台（影像校正界面）：

```bash
restoration serve
# 默认地址 http://127.0.0.1:8000 ，可用 --host / --port 调整
```

界面内的完整操作：

1. **载入原图**：支持 8/16 位灰度或彩色图，界面保留无损处理副本。
2. **掩码与候选依据**：
   - 「生成候选」给出带证据的划痕/灰尘候选，候选只是提案，不会改动掩码；
   - 「把已接受候选并入掩码」是一次显式动作，生成一个新的掩码修订版本；
   - 可直接在画布上用笔刷添加/擦除，每一笔都是一个可追溯修订；
   - 「撤销上一笔」按版本回退，初始空掩码是回退下限；「清空掩码」同样记为一个修订。
3. **执行修复**：选择方法与过渡带等参数后点击「执行修复」。执行瞬间会把当前掩码
   **冻结**为带 SHA-256 身份的快照，处理器只能读取该快照，无法回改界面选区；
   之后继续绘制只产生新修订，不影响已完成的运行。
4. **结果与差异**：界面显示真实原图、冻结掩码、修复结果、4× 放大差异、边界检查
   和推测区，全部来自当次真实修复，没有固定占位数据。报告记录掩码身份、来源修订、
   跨边缘差分（掩码外必须为 0）以及逐样本保留核对。

界面按钮均调用后端划痕修复实现；空掩码会被拒绝而不是静默“成功”，缺少修复参数会
直接报错，不会用默认值掩盖错误。

## 命令行（辅助方式）

命令行仅用于脚本化、批量和评估场景，不替代图形审阅：

```bash
# 仅生成候选与证据，供人工复核
restoration detect IMAGE --out out/detect

# 用人工确认过的掩码执行修复（旧入口，内部已适配到版本化流程）
restoration restore IMAGE --mask MASK.png --out out/run

# 注入已知缺陷做指标评估
restoration benchmark REFERENCE.jpg --out out/benchmark
```

`restore` 是保留的兼容入口：它先把传入掩码冻结成带身份的快照，再交给同一套修复
处理器，因此与图形界面产出的修复行为完全一致。
